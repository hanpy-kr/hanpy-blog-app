# BullMQ - Worker

BullMQ에서 Queue에 추가된 작업을 실제로 처리하는 주체는 바로 Worker입니다. Worker는 기존의 메시지 큐 시스템에서 메시지를 받는 리시버(receiver)에 해당하며, 작업을 받아 처리하고 결과를 반환합니다. 이번 글에서는 BullMQ의 Worker 사용법과 주요 기능에 대해 알아봅시다.

---

## Worker란 무엇인가?

Worker는 Queue에 추가된 작업(Job)을 처리하는 역할을 수행합니다. 작업이 성공적으로 완료되면 해당 작업은 **completed** 상태로 이동하고, 작업 처리 중 예외가 발생하면 자동으로 **failed** 상태로 이동합니다. 실패한 작업은 자동으로 재시도할 수 있도록 설정 가능합니다.

---

## Worker 생성과 기본 사용법

BullMQ의 Worker는 `Worker` 클래스를 사용하여 생성되며, 작업 처리는 프로세스 함수(process function)에서 비동기적으로 이루어집니다.

```javascript title="BullMQ - Worker" showLineNumbers title="BullMQ - Worker" showLineNumbers
import { Worker, Job } from 'bullmq'

const worker = new Worker('myQueue', async (job: Job) => {
  await job.updateProgress(42)
  await job.updateProgress({ foo: 'bar' })

  // 작업 처리 로직
  return '작업 완료'
})
```

Worker 클래스의 인스턴스를 생성하면 기본적으로 Worker는 큐에 연결되어 대기 상태에 진입하고, 작업이 큐에 들어오는 즉시 처리 작업을 수행합니다.



만약 Worker의 작업 처리 시작 시점을 직접 결정하고 싶다면, autorun 옵션을 사용하여 Worker 인스턴스의 자동 실행을 막을 수 있습니다. 이 옵션을 false로 설정하면 Worker는 명시적으로 run() 메서드를 호출할 때까지 작업 처리를 시작하지 않고 대기 상태에 머물러 있게 됩니다. 아래는 Worker의 자동 실행을 비활성화하고 명시적으로 작업 처리를 시작하는 예제입니다.

```javascript title="BullMQ - Worker" showLineNumbers
const worker = new Worker(
  'myQueue',
  async (job: Job) => {
    await job.updateProgress(42)
    return '작업 완료'
  },
  { autorun: false },
)

worker.run()
```

이 방식은 Worker가 필요에 따라 정확한 시점에 작업 처리를 시작해야 하는 상황에서 유용하게 사용할 수 있습니다.

## 작업 결과 및 진행 상태 관리

### 작업 결과(Completed)

Worker의 프로세스 함수는 결과값을 반환할 수 있습니다. 결과값은 작업을 가져와서 `returnvalue`로 확인하거나, `completed` 이벤트 리스너를 통해 확인할 수 있습니다.

```javascript title="BullMQ - Worker" showLineNumbers
worker.on('completed', (job: Job, returnvalue: any) => {
  console.log(`작업 완료됨: ${job.id}, 결과: ${returnvalue}`)
})
```

### 작업 진행 상태(Progress)

작업 처리 과정에서 진행 상황을 보고할 수도 있습니다.

```javascript title="BullMQ - Worker" showLineNumbers
worker.on('progress', (job: Job, progress: number | object) => {
  console.log(`진행 중인 작업: ${job.id}, 진행률: ${progress}`)
})
```

### 작업 실패(Failed)

작업이 실패하면 `failed` 이벤트를 통해 실패 이유를 확인할 수 있습니다.

```javascript title="BullMQ - Worker" showLineNumbers
worker.on('failed', (job: Job | undefined, error: Error, prev: string) => {
  console.error(`작업 실패: ${job?.id}, 이유: ${error.message}`)
})
```

## 전역 이벤트 관리

모든 Worker에서 발생하는 이벤트를 전역적으로 관리할 수도 있습니다.

```javascript title="BullMQ - Worker" showLineNumbers
import { QueueEvents } from 'bullmq'

const queueEvents = new QueueEvents('myQueue')

queueEvents.on('completed', ({ jobId, returnvalue }) => {
  console.log(`모든 Worker에서 작업 완료됨: ${jobId}, 결과: ${returnvalue}`)
})

queueEvents.on('failed', ({ jobId, failedReason }) => {
  console.log(`모든 Worker에서 작업 실패: ${jobId}, 이유: ${failedReason}`)
})

queueEvents.on('progress', ({ jobId, data }) => {
  console.log(`모든 Worker 진행 상황: ${jobId}, 데이터: ${data}`)
})
```

| 항목         | worker.on('failed')       | queueEvents.on('failed')        |
| ---------- | --------------------------- | --------------------------------- |
| 트리거 시점 | Worker가 작업 실행 중 실패했을 때  | 큐 레벨에서 실패 이벤트가 발생했을 때         |
| 동작 범위  | 해당 워커 인스턴스에서 실행된 작업만 감지 | 어느 워커에서든 발생한 실패를 모두 감지        |
| 실시간성   | 즉각적이고 로컬                | Redis Pub/Sub를 통한 비동기 이벤트 스트림 |
| 사용 목적  | 로컬 에러 핸들링, 재시도 로직 등         | 대시보드, 모니터링, 로그 기록 등               |



| 이벤트 종류    | Worker 이벤트 | QueueEvents (전역 이벤트) |
| --------- | ---------- | -------------------- |
| completed |  지원       |  지원                 |
| failed    |  지원       |  지원                 |
| progress  |  지원       |  지원                 |
| error     |  지원       |  없음                 |

Worker 이벤트는 특정 Worker 인스턴스가 처리한 작업에만 적용되는 반면, 전역 이벤트는 모든 Worker 인스턴스에서 발생하는 이벤트를 통합적으로 관리할 수 있게 합니다. Worker 이벤트는 해당 인스턴스에서만 발생하며, QueueEvents는 전체 큐에 대해 모든 Worker에서 발생하는 이벤트를 수신할 수 있습니다. 분산 시스템에서 이벤트 수집 시 유용합니다.

## 오류 처리(Error Handling)

Worker에서 오류가 발생하면 처리하지 않은 예외로 Node.js 프로세스가 멈출 수 있으므로, 항상 오류 리스너를 추가하는 것이 좋습니다.

```javascript title="BullMQ - Worker" showLineNumbers
worker.on('error', (err) => {
  console.error('Worker 오류 발생:', err)
})
```

## 작업 자동 제거(Auto-removal)

기본적으로 큐 작업이 완료되거나 실패하면 각각 "completed" 또는 "failed" 세트에 저장됩니다. 하지만 운영 환경에서는 Redis에 불필요한 데이터가 쌓이지 않도록 작업을 자동으로 제거하는 옵션을 사용할 수 있습니다.

```javascript title="BullMQ - Worker" showLineNumbers
// 모든 완료 작업 즉시 제거
const worker = new Worker(
  'myQueue',
  async job => {
    // 작업 처리 로직
  },
  { connection, removeOnFail: { count: 0 } },
);

// 특정 개수의 작업 보관
const worker = new Worker(
  'myQueue',
  async job => {
    // 작업 처리 로직
  },
  {
    connection,
    removeOnComplete: { count: 1000 },
    removeOnFail: { count: 5000 }
  },
);
```

## Worker의 동시성(Concurrency)

BullMQ에서 동시성을 확보하는 방식은 두 가지입니다.

### 1. 단일 Worker에서의 Local Concurrency 설정

하나의 Worker 인스턴스가 동시에 여러 작업을 병렬로 처리할 수 있도록 concurrency 옵션을 설정할 수 있습니다. Node.js의 비동기 처리 특성과 결합하여 효율적인 자원 활용이 가능합니다.

```javascript title="BullMQ - Worker" showLineNumbers
const worker = new Worker(
  'myQueue',
  async (job: Job) => {
    // 비동기 작업 수행
    return '작업 완료';
  },
  { concurrency: 50 },
);

// 런타임 중에도 값 변경 가능
worker.concurrency = 5;
```

CPU 연산이 집중되는 작업의 경우에는 Sandboxed Processor 방식을 사용하는 것이 더 적합할 수 있습니다.

### 2. 다수의 Worker 인스턴스 운영

여러 개의 Worker 인스턴스를 각각의 프로세스나 서버에서 운영하면 시스템 전체적으로 높은 가용성과 예측 가능한 병렬 처리를 제공할 수 있습니다. 이 방식은 특히 다중 서버 환경에서 권장됩니다.



또한 각 Worker에 높은 concurrency 값을 설정하면 단일 서버에서도 효율적인 자원 활용이 가능해집니다.

## Graceful Shutdown

BullMQ의 Worker는 close() 메서드를 통해 우아한 Graceful Shutdown을 지원합니다. 이 기능은 서버 종료 시점에 새로운 작업을 받지 않고, 현재 수행 중인 작업이 완료될 때까지 대기한 후 안전하게 종료되도록 도와줍니다.

```javascript title="BullMQ - Worker" showLineNumbers
await worker.close();
```

close()는 Worker를 "closing" 상태로 전환하며, 이후 새로운 작업은 처리되지 않고 현재 진행 중인 작업만 마무리됩니다. 이 호출은 기본적으로 타임아웃 없이 동작하므로, 작업 처리 시간 관리가 중요합니다. 만약 강제 종료되거나 실패 시, 해당 작업은 "stalled" 상태로 전환되어 다른 Worker가 재처리할 수 있습니다.



참고로, BullMQ 2.0 이상에서는 별도의 QueueScheduler 없이도 이 기능이 자동으로 작동합니다.

---

## Stalled jobs

Node.js는 단일 스레드 기반의 이벤트 루프 구조를 가지고 있기 때문에, 프로세스 함수가 지나치게 CPU를 점유하면 이벤트 루프가 블로킹되어 BullMQ가 작업 상태를 갱신하지 못하는 문제가 발생할 수 있습니다.

작업이 시작되면 BullMQ는 해당 작업에 락을 걸고, 주기적으로 Worker가 아직 작업 중임을 알리는 신호를 Redis에 보내야 합니다. 이 주기는 stalledInterval 설정에 의해 제어되며 일반적으로 수정을 권장하지는 않습니다.

만약 CPU가 바쁘거나 이벤트 루프가 점유되어 이러한 신호를 제때 보내지 못하면, 작업은 "stalled" 상태로 간주되어 대기 큐로 다시 이동합니다. 이 경우, 다른 Worker가 해당 작업을 재처리하거나, 최대 재시도 횟수를 초과하면 "failed" 상태로 전환됩니다.

따라서 Worker 코드는 반드시 이벤트 루프를 주기적으로 반환하도록 작성되어야 하며, 특히 CPU 연산이 많은 작업은 비동기 방식 또는 워커 스레드/서브프로세스를 사용하는 것이 권장됩니다.

큐 및 워커 일시 중지 (Pausing Queues & Workers)

BullMQ는 큐 전체를 일시 중지하거나, 특정 워커 인스턴스만 일시 중지하는 기능을 제공합니다.

큐 일시 중지

큐를 글로벌하게 일시 중지하면, 모든 워커가 새로운 작업을 가져오지 않습니다. 이미 처리 중인 작업은 완료될 때까지 실행되며, 그 이후에는 워커는 대기 상태로 유지됩니다.

await myQueue.pause();

워커 개별 일시 중지

특정 워커 인스턴스만 일시 중지할 수도 있습니다. 이 경우 현재 처리 중인 작업은 완료되며, 이후 작업을 처리하지 않습니다.

await myWorker.pause();

현재 작업을 무시하고 즉시 일시 중지하려면 다음과 같이 true를 인자로 넘깁니다:

await myWorker.pause(true);

이 기능은 서버 재시작 또는 유지보수 시점에 유용하게 사용할 수 있습니

## 타입스크립트 타입 지정

BullMQ는 타입스크립트를 사용할 때 제네릭을 통해 Job 데이터 및 반환 값의 타입을 명시적으로 지정할 수 있습니다.

```typescript
interface MyData {
  value: string
}

interface MyReturn {
  result: boolean
}

const worker = new Worker<MyData, MyReturn>(
  'myQueue',
  async (job: Job<MyData>) => {
    return { result: true }
  },
)
```
